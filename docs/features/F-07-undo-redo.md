# F-07 Undo/Redo(history middleware)   [real]

**WHAT**: 캔버스 편집 히스토리(실행취소/재실행). `src/stores/canvasEditorStore.ts`(699줄) 내 `pushHistory()` 및 관련 액션들.

**현재상태**: 실동작하나 결함 있음(FACT). `pushHistory()`가 거의 모든 상태 변경 액션에서 디바운스 없이 즉시 호출됨 — 확인된 호출 지점: 258행(`updateFormField`, 키입력마다), 276·284·316·327·349행 등 23개 이상 위치. `updateSlotTransform`(316행)은 슬라이더 틱마다 호출되어 F-02와 동일 근본 문제 공유.

**스펙정합**: Undo/Redo 자체는 에디터 표준 기능으로 스펙과 일치. 디바운스·커밋 단위 설계는 미문서화(성능 비기능요구사항 누락).

**문제·리스크**: 키입력·슬라이더 틱마다 무조건 `pushHistory()` 호출 → JSON-diff 스냅샷 생성 반복(High, 실사용 잭 — 감사 §3.2 성능결함 #1). 디바운스 유틸이 코드베이스에 전무(grep 결과 0건, F-02와 공유하는 근본 원인).

**Fable판정**: **수정** — 키입력마다 push=성능 잭이 명백한 결함. 히스토리 자체의 존재/설계는 정상이므로 재설계 아닌 디바운스+커밋 단위 조정만 필요.

**다음작업**:
1. `pushHistory()` 호출부(258·276·284·316·327·349행 등 23곳)를 감사해 "즉시 커밋해야 하는 액션"(예: 슬롯 추가/삭제)과 "디바운스해야 하는 액션"(텍스트 입력, 슬라이더 드래그)으로 분류 — AC: 분류표 작성, 코드 주석 반영. (Sonnet)
2. 디바운스된 커밋 + ring buffer(히스토리 최대 크기 제한) 도입 — AC: 텍스트 100자 연속 입력 시 히스토리 엔트리 1-2개만 생성, Undo가 여전히 의미 있는 단위로 동작(예: 단어 단위 또는 500ms 무입력 후 커밋). (Sonnet)

**의존·순서**: F-01(CanvasEditor 셀렉터화)·F-02(이미지 슬라이더 디바운스)와 동일 스토어 파일(canvasEditorStore.ts) 수정 — 세 작업을 한 PR 또는 연속 PR로 묶어 회귀 리스크 최소화 권장.
