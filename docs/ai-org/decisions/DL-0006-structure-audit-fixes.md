## 맥락 / 문제
멀티에이전트 라이브 감사(Playwright 실구동 40개 에이전트, 발견 40건 중 37건 CONFIRMED)에서 에디터 신뢰성·수익 게이팅의 구조 결함이 확정됨. 핵심: (1) 프리미엄 내보내기 게이팅이 실 에디터에서 전면 우회(C1·critical), (2) undo/redo 가 텍스트 스타일·스티커·레이어를 복원하지 못함(C2·high), (3) 이미지 undo 시 revoke 된 blob URL 로 슬롯이 깨짐(C3·critical), (4) `/editor/[id]` 가 모든 id 를 couple-magazine 으로 붕괴(A1·high).

## 결정
1. **내보내기 게이팅은 Konva 네이티브 경로에 이식하고 `ExportDialog`(html2canvas 경로)는 삭제.** 두 구현 공존이 C1 의 근본 원인 — 게이팅은 `exportPolicy.ts` 순수 함수 하나로 수렴.
2. **히스토리 스냅샷을 `texts`/`stickers` 배열 참조 + `layerStates`/캐릭터 상태로 확장.** 전체 `templateConfig` 스냅샷은 기각 — 스토어가 두 배열을 항상 불변 교체하므로 참조 저장(구조 공유)으로 충분, MAX 50 스냅샷 메모리 낭비 없음.
3. **blob URL 은 즉시 revoke 금지, 히스토리 수명에 종속.** 스냅샷 탈락 시점(redo 절단·overflow)과 템플릿 전환/리셋에서만 고아 URL 정리. 참조 카운팅은 기각(스냅샷이 유일한 장기 보유자라 과설계).
4. **`/editor/[id]` 는 클라이언트 리졸버로 재작성** (레거시 id/work UUID/템플릿 id 3분류 + 쿼리 보존). 서버 redirect 는 기각 — `?session=` 등 쿼리를 버리는 것이 협업 참가 붕괴(NEW-COLLAB-1)의 공범이었음.
5. **`nanoid` 는 의존성 추가 대신 로컬 `randomId` 로 대체.** 기존 `crypto.randomUUID` 패턴과 일관 + nanoid v5 ESM 의 jest transform 이슈 회피. 비보안 용도(세션 코드)만이므로 충분.
6. **persist 는 templateId 스코핑(v2) + 일치 시에만 병합.** 기존 전역 키는 누출원이면서 소비처도 없는 죽은 무게였음 — 스코핑으로 동일 템플릿 재방문 연속성까지 확보.

## 안 한 것 (근거)
- **F-28 서버 저장 blob URL**(works.editor_data 에 죽은 blob 직렬화): 스토리지 업로드 + RLS 서빙 선행 필요 — CLAUDE.md 게이트대로 defer. 완화만: work 하이드레이션 시 `blob:` 필터링.
- **협업 서버 레지스트리**(C5: localStorage 전용이라 원격 참가 불가): `collab_sessions` 테이블 + Realtime 설계가 필요한 피처 — 별도 트랙.
- **홈 하드코딩 샘플 링크 8건**(A3): 콘텐츠/데이터 시딩 사안. 라우팅 결함 아님.
- **다크모드 반쪽 구현·위스퍼 무음 유실·데모 북마크 무동작 등 신규 발견**: 보고서에 판정·근거 기록, 수정은 우선순위 재조정 후.
