# Model Routing — 작업 분배 원칙

> Fable(두뇌)이 하위 모델(실행 에이전트)에게 작업을 분배하는 기준. 목적: 난도에 맞는 최저 비용 모델로 처리하되 판단은 Fable이 보유.

## 티어 매핑
| 모델 | 역할 | 대표 작업 |
|---|---|---|
| **Fable** (두뇌) | 전략·의사결정·세계관·장기기억·적대검증 최종판정 | 아키텍처 결정, 보안 설계, 스코프 판정(존치/컷/defer), 결정 원장 작성 |
| **Opus** | 난제 실행 | 런타임 마이그레이션, 실시간 협업(Yjs) 배선, 결제 웹훅, 복잡 리팩터 |
| **Sonnet** | 표준 실행 | 기능 구현, 리팩터, 테스트 작성, 문서 전사, 버그 수정 |
| **Haiku** | 경량 작업 | 대량 기계 수정(index-key 교체 등), 코드 탐색, 요약 |

## 분배 규칙
1. **판단이 필요하면 Fable이 먼저 결정**하고, 실행 단계로 쪼개 하위 모델에 넘긴다.
2. 넘길 땐 **1차 근거(파일:라인)** + 수용기준(AC) + 모델태그를 함께 준다(요약만 주지 않는다).
3. **병렬 팬아웃**: 읽기·조사 = Explore 에이전트, 파일 변경 병렬 = worktree 격리.
4. **검수는 독립 에이전트**로: 산출물을 만든 모델이 아닌 다른 에이전트가 적대 검증(정확성/보안/재현).
5. 각 기능의 다음작업 모델태그는 [../features/README.md](../features/README.md) 판정 원장에 부여돼 있다.

## 통신 프로토콜
- 구조화 출력(JSON 스키마) 강제로 전달 손실 방지.
- 에이전트 프롬프트에 "산출 = 데이터, 사람용 메시지 아님" 명시.
- 대용량 출력은 서브에이전트에 격리해 두뇌 컨텍스트 오염 방지.

## 장애 대응
- 에이전트 사망/스킵 → 결과 필터 후 재시도. 백그라운드 완료 알림 기반 재개.
- 부분 실패는 **로그로 명시**(침묵 절단 금지).

## 실사용 예 (이 감사에서)
- Fable: 4대 치명 판정·보안 마이그레이션·이 AI조직 문서.
- Sonnet 병렬 에이전트: 코드베이스 정밀 수집(frontend/backend/security/features), 감사·기능 문서 전사.
- → "단순 수집·전사는 하위 모델, 판단은 Fable" 원칙의 실제 적용.
